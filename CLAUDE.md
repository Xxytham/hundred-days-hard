# 100 Days Hard — notes for Claude

A gym tracker for a 100-day challenge, built for the owner and shared with friends. One HTML file (`app.html`) is the whole app. It ships three ways:

1. **Installed Android app (main one the owner uses).** `android/` wraps `app.html` in a WebView APK. Data lives on the phone. Samsung Health numbers arrive through Health Connect.
3. **iPhone home-screen web app** for friends, at https://xxytham.github.io/hundred-days-hard/ (GitHub Pages, built by `web/build.sh`). Data lives in that phone's browser storage. The friends' download page is `/get/`.
2. **Claude artifact (web).** https://claude.ai/artifact/XAhfUhWMsa4JCgrTkEJTEE, published from `app.html`. Data lives in the artifact's database under the owner's private `data/users/<id>/` path.

The owner is not a programmer and talks to you from a phone. Keep explanations plain, test before shipping, and say what you could not test.

## Ground rules

- **No personal data in code.** Friends install the same app, so defaults stay generic (no goals, generic tasks, start date = today). The owner's own goals and settings live in their saved data, not in `defaultGoals()`/`defaultSettings()`.
- **Never lose the owner's data.** Every change to the stored format needs a migration in `normalizeDay()` (or the matching loader), and old backups must still restore.
- **Never make a new signing key.** The APK is signed with the key in the `KEYSTORE_B64` Actions secret. A different key means the phone refuses the update unless the app is uninstalled, which wipes its data. `android/build.sh` refuses to sign without the real key; use `TEST=1` for local test builds.
- **Bump `android/VERSION` (`code` +1, `name`) for every APK release** and add a `## v<name> · Short description` section to `CHANGELOG.md` (the description, a few plain words, names the release and shows in the app's update banner; leave it off and the banner shows only the version). Pushing a VERSION change to `main` makes GitHub Actions build and publish the signed APK as a Release.
- After changing `app.html`, also republish the artifact (see below) so both versions stay the same.

## File map

| Path | What it is |
|---|---|
| `app.html` | The app: CSS tokens at top, then markup, then one script. Written as an artifact page (no `<html>`/`<head>`; the artifact host and `build.sh` add them). |
| `android/build.sh` | Builds the APK with plain SDK tools (aapt2, javac, d8, apksigner). No Gradle. Downloads the SDK via `setup-sdk.sh` if missing (needs `dl.google.com` allowed). |

| `android/src/.../HealthReader.java` | Reads Nutrition, Weight, Steps, Sleep and Exercise session records (plus Active/Total Calories Burned inside each session's time window, and for walks the Distance and Steps inside it) from Health Connect (Android 14+ framework API, no Jetpack), each only if its permission was granted. Also reads body fat, resting heart rate, HRV (day average), VO2 max, BMR (watts → kcal/day), blood oxygen (day average), heart rate (averaged over each sleep session → `sleepHr`, on the day the night ends), sleep stage minutes (`deepMin/remMin/lightMin`) and the day's calories burned (`burned` total, `active`) into `day.health` (each only if allowed). Prefers Samsung Health's records over other apps' to avoid double counting. Stress, running form and sweat loss aren't in Health Connect, so they can't be read. Sleep counts on the day it ends, minus awake stages. |
| `android/src/.../PrivacyActivity.java` | Rationale screen Health Connect requires. |
| `android/assets/fonts*` | Bundled Google Fonts so the APK works offline. `assets/index.html` is generated, not committed. |
| `tools/wrap_page.py` | Wraps `app.html` into a full document with bundled fonts. Used by both builds; `--pwa` adds the home-screen tags and service worker. |
| `web/` | iPhone web app pieces: `manifest.webmanifest`, `sw.js` (offline cache), `icons/`, `get/index.html` (download page for friends), `build.sh` (outputs `dist/web`). |
| `.github/workflows/build-apk.yml` | On a change to VERSION, the workflow or `web/`: `build` job signs the APK and makes a Release (assets `100-days-hard-v<name>.apk` and a fixed-name `100-days-hard.apk`, so `releases/latest/download/100-days-hard.apk` is always newest), and the `web` job deploys `dist/web` to GitHub Pages. |

## How the app works

Tabs: **Today**, **Stats**, **Progress**, **Goals**. Show less at once and let the user open things; avoid long stacks. Settings order: Goals, Daily tasks, Challenge, Samsung Health, App updates, Share, Backup (the backup dot scrolls straight to Backup). Settings opens from the day counter in the top corner (`gaugeSVG()`: a 300° ring with the gear in the gap at the bottom). In setup, the big inline numbers (`.inline-num`) clear on focus and restore if left empty.

- **First-time setup:** shown while `settings.setupDone` is false (fresh installs only). Steps: welcome ("Welcome to [N] Days Hard", N is an editable number) or restore → "Today is day [n]" with the last day's date → targets → daily tasks (`TASK_PRESETS` plus custom) → Samsung Health (APK only) → done. The targets step picks a calorie goal (Lose fat or Build muscle) and has **Suggest for me** (Katch-McArdle when a body-fat range is picked, otherwise Mifflin-St Jeor; × activity 1.4/1.55/1.75; × 0.8 to lose or 1.1 to build; lose rounds to the nearest 100. Protein is 1 g per lb of lean mass, or 0.8 g per lb of body weight if body fat is unknown, capped at 250 g. The weight entered becomes today's weigh-in. `suggestCheck()` lists what's missing) and **I know my numbers**. Anyone with saved data from before v0.4 is marked `setupDone` on load.
- **Streak:** `streakInfo()` counts consecutive days with every daily task done. Today counts once it's complete; until then the streak runs through yesterday. It's shown on Today with the last 7 days, and the Progress tab uses the same number.
- **Backup dot:** next to the date. `backupState()` is green if `settings.lastExport` (last copy sent off the phone) is within 7 days, yellow within 14, and red otherwise or if there's never been one. It's always green in the Claude artifact once synced. Tapping it opens Settings.
- **Updates:** the APK checks `api.github.com/repos/Xxytham/hundred-days-hard/releases/latest` (uncached) on launch, every time the app resumes, and when Settings opens (at most once a minute). It shows an "Update" banner if the tag is newer than `AndroidBridge.appVersion()`, with the release's description (`updateAbout`, taken from a release name like `v0.9 · Workout button…`, which the workflow builds from the changelog heading). The web app updates itself (network-first page in `sw.js`, with the cache name bumped by version).
- **Sharing:** Settings has "Share with friends": the link `https://xxytham.github.io/hundred-days-hard/get/`, a QR code (qrcode-generator from cdnjs, loaded on demand), plus share/copy buttons. Releases and Pages only work for friends while the repo is **public**.

- **Challenge length:** `settings.totalDays` (default 100) drives the plate, the grid, "Day N of X" and the streak range. When the last day is done (or passed), Today shows a finish card with round stats. "Start another round" appends `{startDate, totalDays}` to `settings.rounds` and makes today day 1. History is never deleted.
- **Tasks that tick themselves:** `METRICS` covers `steps`, `sleep` and `workout` (task ids). The workout count is `workoutParts(day)`, using Samsung Health sessions of 10+ minutes. With a target of 1, a Push/Pull/Legs saved in the app or any cardio session counts. With a target of N ≥ 2 (the owner's rule), it takes one Push/Pull/Legs saved in the app plus N−1 cardio sessions. Walking sessions count as cardio only from 1 mile (`walkCounts`): `miles` comes from DistanceRecords inside the session, falling back to `steps` inside the session ÷ 2,000; a walk with neither doesn't count. Strength-type sessions (Other workout, strength training, weightlifting, calisthenics) never count; their minutes are only shown next to the saved workout. `workoutNames()` adds a "still need …" hint. Target is `settings.workoutsTarget` (default 1; the owner uses 2). Existing users got a one-time card to turn this on (`settings.workoutOffered`). Ticks the app made are recorded in `day.autoTicks` and come off if the value drops below the target; manual ticks clear that flag and stay. Names come from `settings.stepsTarget`/`sleepTarget`. Water used to be read too, but the owner found it unreliable, so it was dropped in v0.5.1; "Drink 3 L of water" is a manual task and old `day.health.waterL` values are ignored. Synced values live in `day.health` and tick the task when they reach the target (never unticking). People who set up before v0.5 get a one-time "Add them" card (`settings.autoOffered`).
- **Tasks count from `addedOn`:** a task with `addedOn` only counts for days on or after it (`tasksFor(date)`), so adding a task never breaks past perfect days or a streak.
- **Stats tab (`renderStats()`):** a Connect card while any watch stat isn't shared (`WATCH_STATS`; "Not now" stores the missing list in `settings.watchOffer` and hides it until that list changes), then a row of section chips (`STAT_TABS`: Strength · Body · Heart · Sleep · Energy; `statTab`; a section shows only once it has data). Strength is `strengthStats()` (`strengthTrend()`: each exercise's est. 1RM against its first session, averaged over all exercises and per day type, drawn with `lineChart()`). The other sections come from the `STATS` list: "line" stats (weight, body fat, BMR, resting HR, HRV, VO2 max, blood oxygen) show the latest reading and its change, green/red by `better`; "bar" stats (sleep, deep/REM/light sleep, calories eaten, protein, calories burned, eaten − burned, steps, workout minutes) show a 7-day average (or total, for `total`) and a 14-day `barChart(m, b)` against the goal. One tile per section is open at a time (`statSel[section]`, first by default, "" when closed). Resting HR uses Health Connect's resting HR if any app shares it, else `sleepHr` (average heart rate during the night's sleep, labeled "average while asleep"). Calories burned is the day's total, or active + BMR. Samsung Health doesn't share HRV, stress, skin temperature or running form. **Progress tab:** Strength tickers (Push/Pull/Legs toggle: `strType` starts on the last workout's type, and tapping the selected one again sets it to null and folds the list), then The N grid with perfect days, streak and average kcal inside it. **Goals tab:** one panel (`renderGoals()`; `newGoalOpen` shows the add form). Open things close in place: tapping an open exercise's row or chart, a body tile or its chart, or a goal's row closes it, and Back closes them too.
- **Apple Health:** not possible from the iPhone web app. It would need a native iOS app and an Apple developer account.
- **Day counter:** `settings.startDate` is day 1 of the current round.
- **Calorie goal:** `settings.calorieAim` is "lose" (default, including for anyone set up before v0.6) or "build". Lose = land within `calorieGoal` ± 100; build = reach at least `calorieGoal`. `calStatus(kcal)` drives Today's meter, the coach line and the calorie trend.
- **Food:** one daily total for calories and protein (the owner logs food in Samsung Health). In the APK these fill in from Health Connect on open/resume. A value the owner types sets `kcalSrc: "manual"`, and synced data never overwrites it. The boxes are the bars (`foodBoxes()`/`foodFill()`): Calories full width and tall, Protein full width and slimmer underneath. The fill is a solid color clipped to `--p` (blue under, green met, red over; protein always green); "Lose fat" scales to 110% of the range top. The number is drawn twice (`.tot-num`): in ink, and in `--on-color` clipped to the same width as the fill, so it flips color where the bar passes under it. The real input sits on top with transparent text and a visible caret. While a box has focus the plain input shows, the fill dims and the bar doesn't move. When the day's totals change (typed and left, or synced), `animateFood()` (run after each Today redraw) counts from what's shown (`foodShown[date]`) to the new value over 700 ms, and `paintFood()` sets `--p`, `--b` (brightness: the fill mixes from `--fade-floor` up to full color as it nears the goal) and `--g` (calories blends blue → green over the last 30% to the goal) every frame. Opening the app or another day draws the bars at their values without animating.
- **Redraws while typing:** a `change` fires as you leave a box, before the next tapped box has focus, so handlers call `renderSoon()` (main page) or `drawWorkoutSoon()` (workout sheet) instead of redrawing on the spot. Otherwise the redraw swaps the next box out from under the tap.
- **Daily tasks:** checklist from `settings.habits`. `protein` auto-checks when the protein goal is met, and `workout` checks when a workout is saved.
- **Workout button:** Today has no Push / Pull / Legs tile. A red + (`#fab`, outside `main`, shown via `body.fab-on` on the Today tab only, hidden while the keyboard is open) opens a small menu (`fabMenu()`) with Push / Pull / Legs and when each was last done; if the day already has a workout, + opens it. The workout card on Today only appears once a workout exists.
- **Typing in the workout sheet:** `onViewport()` spots the keyboard (page or visual viewport at least 120 px shorter than its tallest at this width). While it's open, `body.kb` hides the +, `.sheet.typing` hides the sticky Save bar, and `fitTyping()` scrolls the sheet so the whole card being typed in (for a new exercise: name, weight, reps and Add) sits just above the keyboard. Enter/Next goes name → weight → reps → adds.
- **Workouts (Push / Pull / Legs):** starting a type copies the exercises, order and every set from the most recent *saved* session of that type. Sets are logged one at a time: each exercise keeps `setList: [{w, r}]`, the card edits the current set (`curSet`, starting at set 1), and the Set stepper's + moves to the next set, appending a copy after the last. `weight`/`reps`/`sets` on the exercise mirror its best set (by Epley) and the count, via `syncEx()`, so charts and summaries read them unchanged; `ensureSets()` converts old exercises. Only the first exercise's add form shows an example name. −/+ steps weight by 5 lb (2.5 kg). Exercises with "cable" in the name get an lb/kg toggle that converts the value. A workout autosaves as a draft (`saved: false`) until "Save workout". "Reorder or remove" (`wEdit`) shows one row per exercise (`editRow()`): hold a row about 280 ms (or press its dots, which have `touch-action: none`) to drag it (`startDrag`/`placeDrag`/`endDrag`, pointer events; a non-passive `touchmove` listener stops the page scrolling while a row is held; auto-scroll near the sheet's edges). Tapping a name renames it (`commitRename`); if other workouts have it, `renameAsk` asks Everywhere / Just this workout. `renameExercise()` takes the exact spelling of an existing name with the same key, so histories join, and `mergeSame()` folds duplicates within a workout. Remove has Undo.
- **Strength tickers (Progress tab):** per-exercise "stock ticker". Change is measured on estimated 1RM, `w × (1 + reps/30)` (Epley), so 45×12 → 50×7 reads as a small drop. Bodyweight exercises (weight 0) compare reps. An exercise lists under every day type it was done on (`m.types`: type → its position in that day's latest session), with all its sessions in one chart, "also on …" under its name, and the day type in its session rows. The open exercise is wrapped in `.tick-focus` (outline and soft tint, green unless its last change was down). The open chart has round grid lines, a line/dots/shading colored per stretch (green up or flat, red down), and one upbeat line (`strengthNote()`: gain since the first session, best yet, or the best to aim for) tagged "est. 1RM".
- **Goals layout:** an overall bar, then goals grouped by `groupOf(g)` (keyword guess, or `g.group` set in Edit) into Strength / Cardio / Body, one collapsed row per goal (`openGoal` expands one ladder at a time).
- **Goals:** ladders the owner wrote. Steps are stored easiest → hardest and shown hardest at the top in the open ladder. Each collapsed row shows a strip of three (`goalStrip()`): the step before (grey), the step you're on (the last one ticked), and the next step (the first not done), which is a button that ticks it (`goal-tick`) without opening the ladder. Five slots are drawn so `slideStrip()` can slide them one place left (or right, for the toast's Undo) before the redraw. A tap within 300 ms of a page scroll is ignored (`lastScroll`), so stopping a fling never ticks a step. No steps done shows "Start"; all done shows "All done".
- **Feels like an app:** `buzz(kind)` gives haptics through `AndroidBridge.haptic()` (the WebView's `performHapticFeedback`: no vibration permission; "tick", "confirm", "start", "end"), or `navigator.vibrate` elsewhere. `TAP_BUZZ` lists the actions that tick on tap (tabs, Settings, Progress, every workout-logging control). "confirm" is used for task and goal ticks, adding an exercise, saving a workout, a food bar reaching its goal mid count-up, drags, and pull-to-refresh. Tabs slide in with `slideIn(dir)` (Web Animations, 200 ms). Pull down at the top of Today (APK, Samsung Health connected) to run `healthSync()` (`ptr` touch handlers and `#ptr` indicator: arrow, turns green past 64 px, spins until `__healthResult` or 8 s). Text selection, long-press menus (`contextmenu`) and pinch-zoom are off except in inputs. Toasts are `width: max-content`, so short ones stay on one line.
- **Home-screen shortcuts:** `android/res/xml/shortcuts.xml` (Push/Pull/Legs, icons `sc_*.xml` in plate colors) opens `hundreddayshard://log/<type>`. `MainActivity` (singleTask) keeps it until the page asks (`takeShortcut()` at startup), or calls `window.__shortcut(type)` if the page is already running. That starts the workout, or opens today's if there is one.
- **Backup:** APK writes `Download/100 Days Hard/100-days-hard-backup.json` about 1.5 s after any change (skipped while the app has no data, so a fresh install can't overwrite a good backup). "Send a copy" opens the share sheet. Restore merges by `updatedAt` per document, newest wins. The web version saves to the account automatically and can save/restore the same file.

```
            habits: [{id, name, addedOn?}], setupDone, watchOffer?, autoOffered?, workoutOffered?, finishDismissed?, rounds?: [{startDate, totalDays}], lastExport?, updatedAt }

  kcal, protein, kcalSrc: null|"manual"|"health", weight, habits: {habitId: bool},
  health: null | { steps, sleepMin, deepMin?, remMin?, lightMin?, bodyFat?, bmr?, restHr?, sleepHr?, hrv?, vo2?, spo2?, burned?, active?, sessions?: [{ name, strength, start, min, kcal?, auto, walk?, miles?, steps? }] },   (older days may also hold an unused waterL)

```

## Seeing the owner's progress

- **Web version:** `ArtifactData` `list` on collection `data/users/me` for the artifact URL above. Documents are `settings`, `goals` and one per date.
- **APK:** ask the owner to send a backup (Settings → "Send a copy to Drive or email") and attach the JSON to the chat.

## Shipping a change

1. Edit `app.html` (and `android/` if native code changes).
2. Regenerate test pages with `python3 tools/wrap_page.py android/assets/index.html` and `web/build.sh` (serve `dist/web` with `python3 -m http.server`). Test in Chromium with Playwright at 412×915 (the owner has a Samsung S25 Ultra). To exercise APK-only paths, inject a fake `window.AndroidBridge` with an init script (see the methods in `MainActivity.Bridge`). Check for page errors, and take screenshots for anything visual.
3. Optionally `TEST=1 android/build.sh` to check it compiles. Don't hand that APK to the owner; it won't install over theirs.
4. Bump `android/VERSION`, add the changelog section, commit, push to `main`. That triggers the "Build APK" workflow, which publishes the signed APK to the repo's Releases page. The owner installs it over the old one.
   - Claude sessions can push `main`, but can't push or delete tags, view Actions runs, create releases, or set secrets (the session's GitHub proxy blocks those). Reading releases does work, so check that a build landed with `gh api repos/Xxytham/hundred-days-hard/releases`. Download the asset with `gh api -H "Accept: application/octet-stream" repos/Xxytham/hundred-days-hard/releases/assets/<id>`, and confirm its signer SHA-256 is `9851d428…fb26b` with `apksigner verify --print-certs`. If a build is missing, ask the owner to check the **Actions** tab, or the **Releases** page at https://github.com/Xxytham/hundred-days-hard/releases, and to use **Run workflow** on "Build APK" if a build needs re-running.
5. Republish the web version: `Artifact` read of the URL first, then publish `app.html` with `url` set to it. Keep capabilities `{db: {}, user: {}, downloads: true}`.

## Design

**Motion.** Every animation follows the same rules, so none of them draw attention to themselves:
- Only in answer to a tap, never looping or idle.
- Short: about 200 ms (`--t`), easing out with `--ease`; leaving is quicker (about 120 ms) than arriving.
- Small: moves of about 10 px or one slot, scale no lower than 0.95.
- Cheap: animate `transform` and `opacity` only (a short color fade on a small element is fine). Never animate width, height or position, which force layout every frame. For bars, scale them with `scaleX`.
- Keep animating elements in the DOM and change a class, rather than rebuilding them; new elements skip their transition.
- Everything is switched off under `prefers-reduced-motion`.
One deliberate exception: the food bars count up over about 700 ms, driven by requestAnimationFrame (number, `clip-path` width and color together), because the owner wants to watch them fill.
The pull-to-refresh spinner turns only while Samsung Health is being checked (at most 8 s).
Current uses: the + menu (fade and rise, staggered 30 ms, + turns to ×), the goal strip slide, the food box fill, the sheet rising, rows sliding aside while you drag an exercise, and the Progress focus fading in.

Bumper-plate palette (red 25 kg, blue 20 kg, yellow 15 kg, green 10 kg) over cool steel neutrals, with light and dark themes as CSS tokens on `:root`. Saira Condensed for display, Figtree for body. The owner likes the look, so keep new UI in the same system.
